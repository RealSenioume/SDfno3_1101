## 3. 更远 — 研究

### 3.1 把 lolping 做成 DSH 插件

**想法。** 把轮盘从"ping 记录器"变成 DeepSeek Harness 的**空间指令面**。每个已提交的
扇区变成一条带类型的意图——`search`、`analyse`、`summarise`、`statistics`、`run`——它
携带三件聊天框表达不了的事：用户**指向屏幕的哪里**、那个位置**屏幕上是什么**（窗口
标题、区域）、以及**选中的是哪个扇区**。DSH 消费这条意图并据此行动。

**为什么轮盘是对味的输入。** 提示词是线性的，注意力是空间性的。"看这段日志的这一部分，
数一下错误"包含三个事实——位置、动作、对象——而径向菜单可以在一次手势里交付它们，用户
既不用打字，也不用离开正在看的应用。

**工作形态。**

1. 意图 schema（`lolping.intent/v1`）：扇区 id、动作动词、屏幕坐标、屏幕区域、前台
   窗口、自由文本提示、时间戳、置信度。
2. 传输：先用本地 socket（JSON lines），让插件与 lolping 保持两个进程，任一方崩溃都不
   会拖垮另一方。
3. 一个 DSH 插件：订阅意图，把动词映射到工具（搜索、读文件、统计、截取区域），并把
   进度回报。
4. 结果回传通道：给叠加层的 toast/面板，显示 DSH 正在做什么——由手势触发的静默操作是
   不可接受的。
5. 权限：哪些动词免确认就能跑、哪些需要第二次显式手势；对每条已派发的意图保留追加式
   审计日志。

**风险。** 插件 API 尚未冻结；能触发动作的手势需要一套至少和现在"不注入"立场一样清晰
的权限模型；没有 DSH 在监听时，轮盘必须仍然可用（今天的 ping 行为就是兜底）。

**成本：** L。**目标：** tbd —— 在 v0.4.x 之后，且仅在插件 API 足够稳定可依赖时。
**状态：** 研究。

### 3.2 多人 DSH 协作

**想法。** 多个人各持自己的轮盘，标记同一个共享界面——共享屏幕、文档、回放——每条
意图带署名汇入同一个 DSH 会话。轮盘变成共享的指点工具：三个人同时说"看这块区域"，
各自贡献不同的动词。

**为什么。** 一起复盘一场比赛或一个设计，是单用户日志的自然延伸：ping 列表已经记录了
**标记了什么**，坐标已经记录了**标记在哪里**。把两者变成协作，只差署名与合并。

**工作形态。**

1. 会话服务（先局域网）：用加入码加入，交换标记、光标与意图历史，不需要账号。
2. 身份与署名：每条标记带 peer id 与显示名；叠加层显示是谁的标记。
3. 合并：同一区域上的 N 条意图应作为一次分组请求送达 DSH，而不是 N 条重复——和 ping
   去重是同一类问题。
4. 隐私：标记会暴露注意力；会话必须显式、可见、随时可退出，且没有活跃会话时不上传
   任何内容。
5. 共享结果视图：所有参与者看到同一个答案，而不是各自五份私有答案。

**风险。** 传输与 NAT 穿透、排序标记时的时钟偏差，以及"满屏都是别人的标记"这一社会性
问题。多人还会放大 3.1 的权限面：远端意图绝不能执行本地用户自己的手势也做不到的动作。

**成本：** L。**目标：** tbd。**状态：** 研究。

## 4. 明确不做

来自 `docs/01-proposal.md`：读取游戏内存、注入、Riot API、游戏内 HUD、语音、英雄或冷却
数据，以及任何需要进入游戏进程内部的东西。DSH 插件（3.1）仍然站在这条线的桌面一侧：
它消费意图，不碰游戏。
